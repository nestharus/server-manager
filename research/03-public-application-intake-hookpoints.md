## Notable observations

- There is a proposal-internal path naming inconsistency to resolve in Phase 6a contract definition: the SPA design says `/api/public/applications`, which nginx maps to `/api/v1/public/applications`, while the rate-limit text also names web-host `/api/applications`. This does not invalidate any approved assumption, but Kong bindings must match the actual SPA endpoint chosen by the approved route contract.
- `services/api/app/core/authorization.py` does not exist. The hookpoint is the existing `CedarAuthorizationClient` plus the protected endpoint dependency pattern.
- Synthetic member creation through the existing member service is reusable but carries a member-create audit surface of `api:/api/v1/members`. If public intake needs synthetic-member creation audited as part of public intake, Phase 6a must state that contract before tests are written.
- The Kong application-route policy should be added as normal KIC resources, not by editing the Helm-rendered Kong controller bundle. The rendered bundle is infrastructure substrate; route policy belongs with the application/auth ingresses.
- Current web validators intentionally require Playwright route stubbing. That was acceptable for the old R.22 component contract but conflicts with the approved e2e proof for public intake. Update the validator language so it no longer treats missing e2e interception as a failure.
